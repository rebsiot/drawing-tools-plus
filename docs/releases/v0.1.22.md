# AFT Drawing Tools+ v0.1.22 (Beta) - Editable style presets

## New
- **Customize Presets:** Expand the editor below Outline, Danger, Highlight and Filled. Choose a button, adjust the existing style controls and click **Save [name]**. Changes persist in your client settings; other preset buttons remain untouched.
- **Restore [name]:** Restore just that button to its original built-in colors, width and fill behavior. Discard unsaved edits without changing saved presets.
- While customizing, the style controls edit only a temporary preset draft. They **do not change selected Drawings** until you exit customization and explicitly click a preset in normal mode.

## Fixed
- The floating panel header and its launcher label now say **AFT Drawing Tools+**, matching the Foundry Module Manager entry.

## Unchanged
- This is still the original `foundry-drawing-quickbar` module, so installed worlds, module settings, existing Scene Drawings, native Drawing locks and author permissions, Locate and Multi-Delete remain in place.
- The four original preset buttons behave as before for users who do not customize them. No world-data migration, no additional modules.

## Installation and verification
Back up the Foundry world and module folder. Use the existing Foundry manifest or install the complete v0.1.22 ZIP. Restart Foundry and refresh the browser.

Open **AFT Drawing Tools+**, expand **Customize Presets**, select **Danger**, change its stroke color and click **Save Danger**. Close/reopen the panel to confirm the custom color remains, then click **Restore Danger** to return to the factory style. Test with a disposable selected Drawing: editing a preset should not restyle the object, but clicking a saved preset after exiting customization should.

**Status:** GitHub beta; automated and clean-package checks only. Full live Foundry v14 GM/player, lock, Locate and Multi-Delete regression testing is still required before a stable claim.

**Rollback:** Install [v0.1.21](https://github.com/rebsiot/drawing-tools-plus/releases/tag/v0.1.21). Existing Drawing data is not migrated by v0.1.22; restoring deleted/modified Drawings made during play requires a world backup.
